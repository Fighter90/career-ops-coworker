# Job-Search Coworker — руководство пользователя

Полное руководство по установке и запуску coworker **career-ops** внутри **[OpenWorker](https://openworker.com)**. Coworker превращает OpenWorker в оператора поиска работы: он сканирует доски вакансий, оценивает каждую вакансию относительно вашего CV, готовит обоснованное CV + сопроводительное письмо, ведёт учёт откликов и черновики follow-up — и может открыть для вас дашборд `career-ops-ui`.

## 1. What this is (and isn't)

- **Это** *персона* — один Markdown-файл ([`career-ops.md`](../career-ops.md)) с YAML-frontmatter (какие возможности он запрашивает) плюс системный промпт (как он себя ведёт). «Coworker ⊇ skill».
- **Это не** программа. OpenWorker **не** запускает содержимое этого репозитория как код. Frontmatter *объявляет* проверенные возможности и рекомендуемые коннекторы; промпт *направляет* агента. Именно поэтому на экране установки написано: «no third-party code runs, but the instructions steer the coworker».
- **Он управляет пайплайном [`career-ops`](https://github.com/Fighter90/career-ops)**, а не облачным сервисом. Всё происходит на вашей машине, в вашей папке проекта, с вашим ключом модели.

## 2. Requirements

1. **Установленный OpenWorker** — скачайте с [openworker.com](https://openworker.com) (macOS / Windows) или запустите из исходников. Добавьте ключ модели (Anthropic, OpenAI, Google или локальная модель через Ollama).
2. **Папка проекта `career-ops`** на вашей машине, настроенная с вашими данными:
   ```bash
   git clone https://github.com/Fighter90/career-ops
   cd career-ops
   # следуйте README того проекта, чтобы создать cv.md, config/profile.yml, portals.yml
   ```
   Coworker работает *внутри* этой папки и читает/пишет `cv.md`, `config/profile.yml`, `config/two-pager.yml`, `portals.yml`, `data/applications.md` и `reports/`.

**Файлы, которые вы настраиваете** (полная схема в [README `career-ops`](https://github.com/Fighter90/career-ops)):

| Файл | Что положить |
|---|---|
| `cv.md` | ваше настоящее резюме в Markdown — единственный источник истины, на который опирается coworker (сверх этого он ничего не выдумывает). |
| `config/profile.yml` | целевые роли, грейд, локации, предпочтение по удалёнке, зарплата и `spend_tier` (управляет стоимостью модели). |
| `portals.yml` | доски для сканирования — слаг компании в Greenhouse/Lever/Ashby или запись на всю доску, например `{ name: Torre, provider: torre, search: "engineering manager", enabled: true }`. |
| `config/two-pager.yml` *(опционально)* | нравится / обязательно / стоп-факторы — уточняют оценку соответствия. |

Запустите `node scan.mjs --dry-run` из этой папки один раз, чтобы убедиться, что вакансии подтягиваются, до подключения OpenWorker.

**(опционально)** клонируйте [`career-ops-ui`](https://github.com/Fighter90/career-ops-ui) в `career-ops/web-ui/`, чтобы работала команда *«открой дашборд»* (см. §6).

## 3. Install the coworker into OpenWorker

> **Впервые здесь?** В [README](https://github.com/Fighter90/career-ops-coworker#deploying--running--full-walkthrough) репозитория есть полный пошаговый разбор развёртывания (требования → ключ модели → папка → коннекторы → первый запуск → дашборд → обновление → устранение неполадок). Этот раздел — короткая версия.

1. Получите `career-ops.md` — склонируйте этот репозиторий или скачайте один файл.
2. В OpenWorker: **New coworker → Import** и выберите `career-ops.md` (или укажите OpenWorker на папку этого репозитория).
3. При импорте файл **снимается снимком в управляемую область OpenWorker**. Последующие правки в этом репозитории не меняют установленную копию — переимпортируйте, чтобы обновить; поле `version:` управляет пометкой «replaces vN».
4. Откройте сессию с **Job-Search Coworker** и выберите папку `career-ops` рабочей папкой.

> **Доверие:** устанавливайте только тех coworker'ов, которых вы можете прочитать и за которых можете поручиться — coworker работает с доступом к вашей системе. Этот не содержит кода; всё же сначала откройте [`career-ops.md`](../career-ops.md), чтобы точно знать, как ему предписано себя вести.

## 4. First run

Попросите что-то реальное, например:
- *«Просканируй мои доски и дай топ-5 подходящих вакансий на эту неделю».*
- *«Подгони моё CV под эту вакансию: <вставьте JD или URL>».*
- *«По каким откликам нужен follow-up, и подготовь их».*
- *«Открой дашборд».*

Coworker начинает каждую задачу с короткого плана (панель прогресса), работает по одному этапу за раз и завершает **реальным результатом и указанием, где он лежит** — шорт-лист, файл подогнанного CV, обновление трекера или черновик письма.

## 5. The workflow, stage by stage

- **Scan** — запускает сканер проекта (`npm run scan` → `node scan.mjs`; флаги вроде `--dry-run`, `--company "<Name>"`, `--since 7`). Ноль API-токенов — чистый HTTP к публичным доскам. Сообщает, сколько вакансий и из каких источников.
- **Score fit** — оценивает каждую вакансию **0–5** относительно вашего CV + profile + two-pager, с однострочным обоснованием и конкретными пробелами. Ранжирует и показывает верхушку.
- **Tailor** — по запросу пишет CV под конкретную роль и сопроводительное письмо как файлы (в `reports/` или `applications/`). Обосновано **только** фактами, уже имеющимися в вашем CV; никогда не выдумывает работодателя, дату, метрику или навык и отмечает пробел, а не замазывает его. (`npm run cv:verify-facts` — это гейт правдивости проекта.)
- **Track** — добавляет/обновляет строку в `data/applications.md` с каноническим статусом, который уже использует проект.
- **Follow up** — проверяет каденцию и **готовит** письмо; отправка проходит через подтверждение.
- **Interviews** — по запросу ставит слоты собеседований в календарь и добавляет напоминания о подготовке (через подтверждение).

## 6. Launch the career-ops-ui dashboard from OpenWorker

Попросите *«открой дашборд»*, и coworker запустит локальный веб-UI:
- Предпочтительно: `bash web-ui/bin/start.sh` — при необходимости ставит зависимости и обслуживает на `http://127.0.0.1:4317`. Задайте `PORT=`, чтобы сменить порт, или `CAREER_OPS_ROOT=`, если UI лежит вне проекта. Запасной вариант: `cd web-ui && npm start`.
- Это **долгоживущий, только локальный** сервер (слушает `127.0.0.1`), который читает те же файлы и никуда не отправляет данные. Coworker запускает его в фоне, ждёт ответа `GET /api/health`, затем даёт вам URL.
- Остановите его через Ctrl-C в его терминале или убив процесс `node server/index.mjs`.

## 7. Connections (optional — you approve each)

| Подключение | Зачем | Уровень |
|---|---|---|
| **Gmail** | читать ответы рекрутёров; готовить follow-up / благодарственные письма (отправка через подтверждение) | core |
| **Google Calendar** | ставить слоты собеседований + напоминания о подготовке | core |
| **GitHub** | подкреплять пункты CV вашими публичными проектами и публикациями | optional |
| **filesystem (MCP)** | явно смонтировать папку проекта, если предпочитаете MCP встроенным файловым инструментам | optional |

Подключения объявлены в grant `connectors:` во frontmatter и показаны в панели подключений сессии. Любая запись или отправка всё равно сначала спрашивает.

## 8. Safety model

- **Правдивость — это продукт.** Выдуманный факт в CV может сорвать наём. Каждое утверждение восходит к вашему `cv.md`; каждый подогнанный пункт — то, что вы действительно делали. Если непонятно, подтверждает ли CV утверждение, coworker его опускает и отмечает.
- **По умолчанию только чтение.** Сканирование и оценка бесплатны. **Отправка письма, изменение календаря, запись вне проекта или перезапись `cv.md` — через подтверждение** — coworker сообщает, что он сделает, и ждёт.
- **Локально и приватно.** Ваше CV, цифры зарплаты и отчёты остаются на вашей машине и никогда не публикуются в коннектор, который вы не запрашивали.

## 9. Scheduling (automations)

Coworker объявляет `scheduling: true`, поэтому в OpenWorker можно настроить периодические запуски — например **утренний брифинг сканирования** («каждый будний день в 8 утра сканируй и давай топ новых подходящих вакансий») или **еженедельный обход follow-up**. Запуски попадают в приложение с полными транскриптами; запуски без присмотра паркуют запросы на подтверждение в inbox, а не действуют сами.

## 10. Troubleshooting

- **«Вакансий не найдено».** Убедитесь, что в `portals.yml` перечислены включённые компании/доски и что ваша сеть до них дотягивается (некоторые региональные доски блокируются полнотуннельным VPN — отключите его и просканируйте снова). Попробуйте `npm run scan -- --dry-run` для предпросмотра.
- **Дашборд не открывается.** Убедитесь, что установлен Node ≥ 18 и порт 4317 свободен (`PORT=8080 bash web-ui/bin/start.sh`). Проверьте `http://127.0.0.1:4317/api/health`.
- **Подогнанное CV выглядит скудным.** Это работает гейт правдивости — он не выдумывает опыт. Добавьте реальные свидетельства в `cv.md` (или в ваш GitHub) и подгоните снова.
- **Coworker не отправляет письмо.** Так задумано — отправки через подтверждение. Подтвердите check-in или смените режим разрешений в OpenWorker, если хотите меньше запросов (сначала осознайте компромисс).

## 11. Update & uninstall

- **Обновление:** обновите этот репозиторий (или заново скачайте `career-ops.md`) и переимпортируйте в OpenWorker; повышение `version:` покажет пометку «replaces vN».
- **Удаление:** уберите coworker в списке coworker'ов OpenWorker. Файлы вашего проекта `career-ops` не тронуты — coworker только читал и писал файлы, которые вы одобрили.

## 12. FAQ

- **Нужны ли мои данные в облаке?** Нет. Всё локально; что-либо видят только выбранная вами модель и коннекторы — и только то, что вы одобрили.
- **Какие модели лучше?** Сильные модели с tool-calling (frontmatter рекомендует `anthropic:claude-opus-4-8` и `openai:gpt-5.5`); подойдёт и мощная локальная модель через Ollama.
- **Может ли он откликаться на вакансии за меня?** Он готовит всё — подогнанное CV, сопроводительное письмо, строку трекера, follow-up — но любое внешнее действие (отправку) одобряете вы. Это coworker, а не автопилот.
- **Связано ли это с OpenWorker?** Нет. Проект нацелен на формат coworker'а OpenWorker и open-source-проект `career-ops`; оба под лицензией MIT.
